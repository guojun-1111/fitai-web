## 正文

---

做健身 App 时遇到一个看似简单、实则很难的问题：

**用户连续几天恢复分数偏低，到底该提醒他「今天状态差，多休息」，还是该警告他「你已经在过度训练边缘，必须减量」？**

前者是单日离群点（outlier），后者是生理基线的持久偏移（changepoint）。混淆这两者，要么让用户错过减量的窗口、练到受伤，要么天天弹「该休息了」变成狼来了。今天分享我在开源项目 FitAI-Web 里用的一个算法：CUSUM + 贝叶斯因子双轨变点检测，纯 Python 标准库，没有一行 numpy。

### 为什么均值 / 阈值不够

最直觉的做法是「恢复分数低于阈值就告警」。但它有三个致命问题：

1. **阈值是拍脑袋的**。低于 50 分算差，那 51 分算不算？
2. **对单日波动过敏**。昨晚没睡好，今天掉到 45，明天回 60——这是噪声，不是趋势。
3. **看不出「持续性」**。真正危险的是「连续 5 天每天低一点点」，但每天的绝对分数都不算低。

我们要检测的不是「某个值低」，而是「**生成这个值的分布本身变了**」。这就是变点检测。

### 核心思想：两条互补的轨

**轨 1：自适应 CUSUM（对慢漂移敏感）**

把每天的观测标准化成 z 分数，然后累计：

```
S_t = max(0, S_{t-1} + z_t - drift)
```

- `z_t = (观测值 - 预测值) / 预测标准差`，是把「偏差」换算成「几倍标准差」；
- `drift`（我取 0.2）是每步减掉的一个小常数，防止慢吞吞的随机波动把累积和「攒」起来误报。

关键就在这个 `max(0, ...)`：一旦观测回到正常，累积和立刻归零。**只有「连续、同方向」的偏差才能把 S_t 推到阈值（5.0）以上。** 单日掉分、第二天反弹，攒不起来；连续一周每天偏低一点点，就会越过阈值——这正是我们要区分的两种情形。

```python
self.cusum_pos = max(0.0, self.cusum_pos + z - self.drift)  # 观测 > 预测
self.cusum_neg = max(0.0, self.cusum_neg - z - self.drift)  # 观测 < 预测
```

正向和负向分开记，变点之后还能区分是「退化」还是「变好」。

**轨 2：贝叶斯因子（对突变敏感）**

CUSUM 对「每天低一点点」很灵，但对「某天突然暴跌」反应慢。所以我加了第二条轨——用贝叶斯因子比较两个假设的证据比：

```
BF = P(观测 | 近期模型) / P(观测 | 长期基线模型)
```

观测在哪个模型下更「合理」，证据就偏向哪边。我用了 Student-t 分布做似然（比高斯更抗离群点），长期基线用 EWMA 在线更新均值和方差。累积 log BF：

- `log BF > ln(20)` → 强变点证据（决定性，Kass & Raftery 1995）
- `log BF > ln(3)` → 中等证据
- `log BF < ln(1/3)` → 强「无变点」证据

```python
ll_baseline = _student_t_logpdf(obs, df=baseline_n - 1, mu=baseline_mean, sigma=baseline_std)
ll_reference = _student_t_logpdf(obs, df=1, mu=baseline_mean, sigma=50.0)  # 宽参考
self.log_bf += ll_reference - ll_baseline
```

两条轨互补：**CUSUM 抓慢漂移，贝叶斯因子抓突变**，任一触发即判定变点。

### 落地效果

在 FitAI-Web 里，这个检测器挂在贝叶斯恢复模型之后：模型每天给出「预测恢复分数 + 不确定性」，检测器判断「实际值是否持续偏离预测」。触发退化变点时，会给用户一段可解释的提示：

> 「恢复分数持续低于预测（CUSUM=6.2），可能为过度训练早期信号。建议减少训练负荷 30-50% 并增加睡眠。」

关键不是「告警」，而是**告警带着方向（退化/变好）和证据强度（强/中）**，用户知道为什么、该怎么做。

### 一点工程体会

1. **纯 Python 够用**。这个检测器每用户每天 O(1) 更新，`math.lgamma` 算 Student-t 的对数归一化常数，不需要 numpy。1 核 VPS 上跑几千用户毫无压力。
2. **解释性比准确率重要**。健康建议是高后果场景，输出「CUSUM 值 + 方向 + 证据」比输出一个黑盒分数可信得多——用户敢照着做，前提是他看得懂。
3. **先验要保守**。`hazard_rate` 默认 1/100 天，宁可漏报也别误报，健身场景误报「你过度训练了」的代价远大于晚一天提醒。
